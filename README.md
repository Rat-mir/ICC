# ICC — Interactive Character Catalog

Курсовой проект по заданиям КП 3–12 курса «ИС-24-22б Основы backend». Основан на файлах ICC_КП2.docx и ICC_Техническое_задание_ICC.docx.

REST API на **Laravel 13 / PHP 8.3+ / MySQL 8.4 / Sanctum 4**, отдельный веб-клиент на HTML/CSS/JavaScript. Проверено с PHP 8.4.19, Laravel 13.40.0; зависимости закреплены composer.lock.

Реализованы 7 сущностей, миграции и фабрики, роли user/creator/admin, PNG-элементы и порядок слоёв, сохранение персонажей, PNG-экспорт в браузере, публикации, комментарии и лайки, модерация мейкеров, поиск/фильтры/сортировка/пагинация, статистика, CORS, журналирование и Feature-тесты.

## Быстрый запуск на этом компьютере

Откройте PowerShell в папке проекта и запустите:

    powershell -File .\Start-ICC.ps1

Скрипт использует установленный PHP из C:\OSPanel\modules\PHP-8.4 либо PHP из PATH. Для быстрой демонстрации создаёт SQLite-базу, если .env отсутствует. Открывает два локальных сервера: API — http://127.0.0.1:8000, клиент — http://127.0.0.1:5173. Серверы останавливаются нажатием Enter в том же окне. Перед первым запуском из архива выполните composer install.

SQLite предназначена для демонстрации и автотестов. Основной вариант по ТЗ — MySQL 8.4, настройка ниже.

## Установка с MySQL 8.4

Требования: PHP 8.3+ с pdo_mysql, pdo_sqlite (для тестов), gd, fileinfo, mbstring, openssl, curl, xml, dom; Composer 2; Git. В php.ini задайте upload_max_filesize=6M, post_max_size=8M. Не устанавливайте post_max_size ниже лимита 5 МБ на файл.

1. Распакуйте проект. Выполните composer install.
2. Создайте отдельную базу icc с utf8mb4 и отдельного пользователя с правами на эту базу.
3. Скопируйте .env.example в .env; укажите DB_HOST, DB_PORT, DB_DATABASE, DB_USERNAME и DB_PASSWORD.
4. Выполните:

       php artisan key:generate
       php artisan migrate --seed
       php artisan serve --host=127.0.0.1 --port=8000

5. Во втором терминале из корня проекта:

       php -S 127.0.0.1:5173 -t client

6. Откройте http://127.0.0.1:5173. Проверка API: http://127.0.0.1:8000/api/health.

Адрес API задаётся только в client/config.js. Адрес клиента для CORS — CLIENT_ORIGINS в .env; при изменении выполните php artisan config:clear. Поддерживаются http://127.0.0.1:5173 и http://localhost:5173, wildcard не используется.

Не запускайте migrate:fresh на базе с нужными данными. Для полной демонстрационной пересборки только собственной тестовой базы: php artisan migrate:fresh --seed.

## Демонстрационные аккаунты

| Роль | Email | Пароль |
|---|---|---|
| Администратор | admin@icc.test | DemoPass123! |
| Креатор | creator@icc.test | DemoPass123! |
| Пользователь | user@icc.test | DemoPass123! |

Эти учётные записи предназначены для локальной демонстрации. Регистрация создаёт только user; admin назначает роль creator через раздел «Аккаунты».

Сидер создаёт 10 пользователей, 10 мейкеров, 60 PNG-слоёв, 10 персонажей, 10 публикаций, 10 комментариев и 10 лайков. PNG рисуются локально через GD, внешние ассеты и сетевые сервисы не нужны.

## Демонстрационный сценарий

1. Войдите как creator. Откройте «Мастерская», создайте мейкер.
2. Загрузите PNG body и face одинакового размера (примеры после сидирования лежат в storage/app/private/demo). Настройте названия и порядок.
3. Отправьте заявку. Повторная отправка и правка pending дают 409.
4. Войдите как admin. В «Модерация» откройте заявку, верните с комментарием.
5. Креатор исправляет набор и отправляет снова. Администратор одобряет.
6. Гость открывает каталог, собирает персонажа, меняет порядок слоёв и скачивает PNG.
7. Пользователь сохраняет персонажа, публикует изображение, пишет комментарий, ставит/снимает лайк.
8. Admin скрывает опубликованный мейкер/пост и при необходимости блокирует аккаунт. Сервер проверяет роли независимо от скрытых кнопок.

## Тесты и документация

    php artisan test
    php artisan route:list --path=api

Тесты используют SQLite :memory: и RefreshDatabase, не рабочую базу. Основной набор — tests/Feature/IccApiTest.php. Проверяются успешные операции, валидация PNG, владение данными, роли, переходы модерации, откат, M:N, лайки, фильтры, пагинация и CORS.

В ограниченной среде Codex на Windows проверка is_readable может возвращать false, хотя файлы читаются. Для этой среды создан phpunit.local.xml с теми же тестами и без повторной bootstrap-проверки. Фактически выполненная команда и результат записаны в docs/verification.md и docs/test-output.txt. На обычном компьютере используется стандартная команда выше.

API: docs/API.md, docs/endpoints.csv, docs/ICC.postman_collection.json. В Postman импортируйте коллекцию, задайте base_url, выполните Login нужной роли; скрипт запроса сохраняет token в переменную. Все запросы имеют Accept: application/json; защищённые — Bearer {{token}}.

Материалы КП: docs/reports/КП_03.docx … КП_12.docx, docs/physical-model.md, docs/physical-model.png, sql/schema.mysql.sql, sql/seed.mysql.sql, sql/joins.sql, docs/join-results.md, docs/test-cases.csv, docs/test-results.xml. Отчёты указывают ограничения реально выполненной проверки.

## Структура

| Каталог | Назначение |
|---|---|
| app/Enums, app/Policies | Статусы, роли, владение объектами |
| app/Http/Requests | Серверная валидация на русском |
| app/Http/Controllers/Api | Контроллеры REST |
| app/Services | Бизнес-правила и транзакции |
| app/Http/Resources | Разрешённые поля JSON |
| database | Миграции, фабрики, демонстрационный сидер |
| client | Самостоятельный клиент с fetch |
| sql, docs | Физическая модель, API, материалы КП |

PNG хранятся в приватном хранилище и выдаются через API с проверкой прав. storage:link для них не нужен. Пароли и токены не включаются в журнал API; безопасная выдержка — docs/api-log.txt.

Уточнения модели: asset_character.layer_order для индивидуального порядка слоёв, статус hidden для административного скрытия. См. docs/business-rules.md. История всех решений модерации и версии PNG в минимальную модель не входят.

Для публичного размещения настройте HTTPS, CLIENT_ORIGINS и реальные секреты, удалите/смените демонстрационные аккаунты. .env и vendor не включаются в Git/архив исходников.
